# Beta cloud rendering corrections

Compared with the official [Tokyo source](https://github.com/takram-design-engineering/three-geospatial/blob/main/storybook/src/clouds/3DTilesRenderer-Story.tsx).

The Tokyo demo reconstructs sun and sky lighting in AerialPerspective for its photographic tiles. Polyform already lights PBR geometry with SunLight and SkyLight, so enabling those postprocess lighting switches would light the scene twice. With both switches off, AerialPerspective computes cloud transmission but does not apply it to input radiance. The cloud shadow texture therefore had no receiver in the previous integration.

CloudMaterialShadows now reads the library's cascaded Beer shadow maps, ECEF transform, sunlight direction and atmospheric altitude correction. Material shader hooks attenuate direct directional radiance using optical depth; ambient skylight, environment reflections, emissive surfaces and indoor point/spot lights remain intact. Existing material hooks (including procedural vegetation deformation) are chained and restored. Standard and physical materials receive these shadows, including terrain, vegetation and furnishings. Unlit/basic/custom shader materials are outside this receiver path. Cloud shadows require Physical sky and the global viewport Shadows setting.

Filtering uses a fixed 3x3 kernel rather than random sample rotation on each surface pixel. New mounts invalidate cached material uniforms without preventing shader sharing within a mount. This avoids stale shadow textures after cloud toggles. Disabling clouds or Beta restores the original material hooks.

The library's temporal upscale internally renders one ray per 4x4 output block. Combining it with our Low resolution scale of 0.5 meant one ray per 8x8 full-resolution block, with fresh pixels bypassing temporal accumulation. We now use its temporal antialiasing resolve at Low 0.5, Medium 0.75 and High 1.0 resolution. This increases cloud ray work in exchange for substantially cleaner clouds; Low still limits detail, march count and shadow map size. The final dithering pass was also removed (the Tokyo demo actually includes the same pass; its sub-byte amplitude alone does not explain the original heavy grain). No unlicensed noise asset was introduced.

Verified in the real Polyform viewport using a 3km PBR ground plane: cloud shadow footprints appear with clouds enabled, vanish when disabled and return after re-enabling. Low and High presets compile without shader errors and the clear sky/PBR surfaces remain smooth. Automated checks cover original material-hook preservation, directional-only attenuation, cleanup and uniform-cache invalidation. TypeScript and the production build are also checked. Mobile GPU timing and the user's exact saved scene have not been measured.
